Status: `built_pending_conformance`

Requires: `acquisition_registry`. Produces: `aligned_layers` (COGs on the 0.01 degree grid, snapped for 0.05 degree nesting), distance rasters with `distance_capped` flags.

## Active implementation decisions

- **D-F2a-001 — Legacy grid_alignment ported with targeted revisions.** `grid_alignment` preserves the legacy's validated scientific logic where applicable, with specific, individually justified revisions (geodesy centralization, resolution fixed, distance cap) rather than a full rewrite or an unreviewed port.
  Archive: docs/_archive/2026-09/DECISIONS.md 2026-09-08 - grid_alignment (Fase 2a) portado do legado
- **D-F2a-002 — Bowring centralization, unified distance cap, fixed resolution.** Bowring geodesic calculations are centralized in `core/geodesy.py`; grid/road/river distance search uses one unified cap rather than a different value per feature (to be exposed as `distance_cap_km` per M-F2a-03, not the current hardcoded constant). The 0.01 degree fixed (non-adaptive) resolution is implemented; snapping bounds so 0.05 degree cells nest exactly (5 x 5 pixels) is not implemented — this decision is **partially conformant** with M-F2a-01 as written (see the M-F2a-01 conformance row and the TODO under Known issues). The fourth verdict of this same entry (retaining the wind AHP combination matrix) is retired — see `docs/_audit/2026-09_records.md` migration report, invalidated by M-F2a-04.
  Archive: docs/_archive/2026-09/DECISIONS.md 2026-09-09 - Passo 4: os 4 veredictos metodológicos de grid_alignment
- **D-F2a-003 — Fail-loud on corrupted land-cover tiles.** `mosaic_land_cover` fails loudly when a tile overlapping the country is corrupted, rather than silently absorbing an integrity failure of a file that is present.
  Archive: docs/_archive/2026-09/DECISIONS.md 2026-09-11 - grid_alignment: mosaic_land_cover fail-loud em tile corrompido

- **D-F2a-004 — Distances are stored uncapped; `distance_cap_km` only flags (OQ-040, METHODOLOGY 2.0.0, Douglas's authorization 2026-10-06).** D-F2a-002 unified the cap at 100 km, which was inert while distances only fed 5-30 km proximity decays. Once distances became monetized cost drivers (M-F6-01) a cap understates the connection CAPEX, and the LCOE, of remote cells. The literature gives no universal distance limit and puts distance into site cost continuously (`docs/_audit/2026-10_distance_connection_cost_evidence.md`). So the rasters keep the real geodesic distance, the old constant `LINEAR_FEATURE_MAX_DIST_KM` is removed, and `distance_cap_km` (a `settings.yaml` value, 100 km provisional and unsourced, L-019) only defines the flag raster written beside each distance raster, a quality indicator (the eligible-area share beyond it is reported per cell by F3). Douglas's stated direction for the cost side, beyond this change, is to model connection cost as a function of the real distance and of infrastructure characteristics (OQ-041); that needs sourced data per country and is not done here.

- **D-F2a-005 — Wind is aligned per height; the AHP combination is removed (G-2, 2026-10-06).** M-F2a-04 forbids combining heights in F2a. The legacy `combine_wind_layers()` blended 50/100/200 m wind speed with AHP weights (Saaty, 1980, unsourced judgments) into one raster, and only for wind speed. Now every GWA product acquired in F1 (M-F1-03: wind speed, Weibull A, Weibull k, air density at 100, 150 and 200 m, 12 layers) is reprojected on its own, which is what F2b/H-4 and F5 (Weibull A/k and air density per hub height, M-F5-03) need. `GridAlignmentResult.wind` (one raster) is replaced by `wind_layers` (a dict keyed `<product>_<height>m`); older manifests carrying `wind` no longer validate and need `rerun_phases` for `grid_alignment` (PRT's entry was already stale). The legacy F2b criterion `wind_resource` now receives the 100 m wind speed (one height, not a combination) until H-4 replaces it with the per-height resource layers.

- **D-F2a-006 — Slope uses geodesic pixel spacing (G-1, 2026-10-06).** `derive_slope_from_dem()` kept its method (central-difference `numpy.gradient`, nodata masked before the gradient) and replaced the spherical spacing (`dy = res_y * 111.32 km/deg`, `dx = res_x * 111.32 * cos(lat)`) with the WGS84 metres per degree at each row's latitude (`core.geodesy`), as M-F2a-02 requires. Measured effect on the native DEMs (2026-10-06, whole DEM, new minus old): PRT 622,393 valid pixels, max |difference| 0.055 degree, p99 0.021, median 0.0016, mean slope 2.5275 -> 2.5286; BRA 52,118,725 valid pixels, max 0.190 degree, p99 0.061, median 0.0010, mean slope 1.9050 -> 1.9097. The change is small (largest where slopes are steep); the V-01 fixtures still need the G-4 refreeze, which needs Douglas's authorization. The Horn 8-neighbour method (as in `gdaldem`) was not adopted; that would be a separate decision.
- **D-F2a-007 — The adaptive-resolution mode and the duplicated schema defaults are removed (G-3, 2026-10-06).** The method fixes the resolution (M-F2a-01, 0.01 degree snapped for 5 x 5 nesting); the legacy "adaptive" computation was never the configured value and its `target_pixels` had no calibration. `AdaptiveResolutionConfig`, the `adaptive` settings block and `GridAlignmentInputs.adaptive_*` are deleted. Resolution and the distance flag threshold are required, no-default values read only from `settings.yaml` (CONVENTIONS).

- **D-F2a-008 — F2a follows the A-08 layout (G-3, 2026-10-06).** Aligned rasters, the distance flag rasters and `<ISO3>_grid_metadata.json` are written to `outputs/<ISO3>/grid_alignment/artifacts/` (they used to sit directly in `outputs/<ISO3>/grid_alignment/`); the vector clip cache and the native-resolution slope temp file go to `interim/<ISO3>/grid_alignment/` through `core.paths.interim()` (they used to share `outputs/<ISO3>/processed/` with data_quality_audit by disk-file convention). Consequence: F2a no longer reuses F1b's clip cache and recomputes the clips once per country (a time cost only); moving F1b's own `processed/` cache is F1b's decision. Tests isolate `GEOFREA_DATA_DIR` per test so the interim cache cannot leak between tests.

- **D-F2a-009 — GWA Weibull A/k tiles carry no CRS; the CRS comes from the same-height wind-speed tile, or the phase fails (2026-10-06).** A PRT run of `grid_alignment` stopped at `weibull_a_100m` with a rasterio CRS error. Scan of `raw/gwa/`: all Weibull A and k files (3 countries x 3 heights x 2 products) declare no CRS, while wind-speed and air-density files declare EPSG:4326, on the same grid (the GWA API serves the Weibull tiles untagged). `reproject_to_grid()` now raises `MissingSourceCrsError` for any source without a CRS unless a `src_crs` is given, and `alignment.py::_gwa_crs_for()` supplies the wind-speed sibling's CRS only if its transform and shape equal the layer's own, else it raises. The raw files are not rewritten. Tests in `test_grid_alignment_raster_alignment.py` (2 new). This was a real F1 data gap exposed by G-2: until then only the 100 m wind speed was aligned.

- **D-F2a-010 — V-01 refrozen on the synthetic ZZZ country; the legacy PRT/BRA baseline is retired (G-4, Douglas's authorization 2026-10-06).** Douglas authorized overwriting the frozen baseline and reducing the fixture set to F1, F2a and E1-E3. It needs no external data, so CI no longer downloads anything; the workflow was rewritten. Also fixed: `generate_zzz_fixture.py` had drifted from the loader (it wrote the power plants as GPKG, the loader reads CSV). Not covered: real PRT/BRA parity (their aligned outputs are inspected in F1b/F2a records, not frozen); the old release asset and `regression-fixtures.tar.gz` can be deleted when Douglas decides. Layers frozen: F2a aligned rasters (distances raw plus `_capped` flags, per-height wind, slope, land cover, population, plants, lakes), E1, E2.

## Known issues

- **M-F2a-01 resolved (G-3, 2026-10-06).** `build_reference_grid()` used to snap only to the 0.01 degree pixel, so 0.05 degree cells did not nest. It now snaps to `resolution x nesting_pixels` (0.05 degree) and the F2a call passes 5; the old floor/ceil also carried float noise (a bound exactly on the lattice could gain a spurious extra row/column), replaced by a tolerant snap. A test fixture that relied on that noise to have pixels outside the country mask was changed to a triangle. Existing PRT/BRA/IND grids change extent by up to 4 pixels per side, which is part of the V-01 refreeze (G-4).

- **Memory known issue resolved (G-5, 2026-10-06).** `reproject_to_grid()` used to call `src.read(1)` on the whole source for its NaN-sanitizing guard (BRA `population`: (46814, 54172) float32 = 9.45 GiB, `MemoryError`, which deleted BRA's F2a output on 2026-09-22). It now processes the destination in horizontal strips, each reading only the source window it covers plus a pad of the resampling footprint, sized to `_REPROJECT_WINDOW_BYTES` (400 MB; parameter `max_window_bytes`); the NaN guard runs per window and logs one aggregated warning. Strips give the same raster as a single pass (`test_windowed_strips_give_the_same_raster_as_a_single_pass`), no call sees the whole source, and a non-overlapping source yields all nodata. Real-data check 2026-10-06: BRA `population` (mainland grid 3905 x 3925) reprojected in 83 s with 6,996,123 valid pixels, no memory error (peak working set was not measured reliably, the bound is by construction). Not changed here: the layer is resampled bilinearly although it holds counts per pixel (ADJ-2); the count-preserving treatment belongs to H-3's population-density conversion.
