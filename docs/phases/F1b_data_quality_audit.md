- **D-F1b-006 — CRS assigned to Weibull-A/k from an exact-match reference, at read time only; grid identity confirmed across all 36 product/height/country combinations (task F1-3, 2026-09-23).** Follow-up to D-F1b-005 below, which found the gap but deliberately did not fix it. Two things verified before any code changed, per file metadata, not assumption:
  1. **Resolution/dimensions (M-F1-03, OQ-027):** for all 4 products x 3 heights x 3 countries (36 files), `rasterio` reports identical pixel size (0.0025 deg), width, height and bounds per country, regardless of product or height — the file-size difference (PRT: 4.5-4.7 MB for `air-density` vs 14.7-16.8 MB for the other three, same extent) is compression only (a smoother field compresses harder under the shared ZSTD/COG layout), not a coarser grid. OQ-027 stays closed on the single 0.0025 deg figure; `config/audit.yaml` is unchanged by this finding.
  2. **CRS identity:** `combined-Weibull-A`/`combined-Weibull-k` (no embedded CRS) were compared field-by-field against `wind-speed` (EPSG:4326) at the same country and height — `transform`, `bounds` and `(width, height)` all compare exactly equal (`==`, not within-tolerance) for all 18 pairs (2 products x 3 heights x 3 countries). Assigning EPSG:4326 to the two CRS-less products is therefore an observed fact, not an inference.

  Implementation, in exactly one place: `raster_inspection.py::_effective_crs()` (new), called from `inspect_raster()` right after opening the file. If the file has a CRS, that CRS is used unchanged. If not, and a reference path was given (`inspect_raster(..., assume_crs_from=...)`), the reference is opened and its `transform`/`bounds`/`(width, height)` are compared to the target; only on an exact match is the reference's CRS borrowed, purely in-memory (`geopandas.to_crs()` calls inside `_mask_raster_by_polygon()`/`_stats_chunked()`, both now taking an `effective_crs` parameter) — the downloaded file itself is never opened for writing, so its `source_sha256` (computed at fetch time, D-core-016) stays meaningful. No reference given, or the reference disagrees (`CrsAssumptionMismatchError`), or the file has a CRS to begin with is not needed (`MissingCrsWithNoReferenceError`) — every other case fails loud, not a silent default. `audit.py`'s `raster_map` loop passes `assume_crs_from=inputs.wind_paths[0]` for `weibull_a`/`weibull_k` only (`_crs_reference_by_layer`), since that's the pairing verified above; no other layer requests this.

  Real result, BRA and PRT: `weibull_a`/`weibull_k` now inspect cleanly (`crs=EPSG:4326`, real stats) — Weibull A means ~4.3-6.4 m/s, Weibull k means ~2.0-2.3 (physically plausible wind-resource shape parameters), air-density means ~1.12-1.17 kg/m3 (physically plausible at these countries' elevations). `not_audited` stays free of every `wind/*` entry, same as before this fix; the earlier `[MISSING] ... Must pass either crs or epsg.` finding no longer appears.

- **D-F1b-003 — land_cover tile cache: sha256 content check added; hit condition and its remaining gap recorded, OQ-026 extended.** Cache mechanics as of `raster_inspection.py` (`_land_cover_tile_cache_key`, `_load_land_cover_tile_cache`/`_save_land_cover_tile_cache`, called from `inspect_land_cover_tiles()`; wired in `audit.py`'s `land_cover_cache_dir`): one JSON file per tile at `outputs/<country>/data_quality_audit/land_cover_tile_cache/<tile_stem>.json`, holding that tile's CRS, resolution and per-class area contribution. A hit requires the tile's mtime, size, and sha256 of its own bytes, plus a sha256 of the masking country polygon's WKB, to all match a `cache_key` string stored alongside the payload — not path existence alone. Added 2026-09-23: the sha256 of the tile's bytes (`_file_sha256()`), closing the gap where the first version (2026-09-22, mtime+size only) could not tell a same-size/same-mtime content change (e.g. a tile silently re-downloaded or restored with a copied timestamp) from an unchanged tile. The polygon fingerprint already covered a changed island-filtering rule or a different `country_gdf`. Remaining, real gap: the key carries no version of the per-tile computation algorithm itself — if `inspect_land_cover_tiles()`'s class-area logic changes (a bug fix, a different windowing strategy), an old cache entry computed under the prior logic is silently reused forever, since nothing about the code version is in the key. Added as a second instance to OQ-026 (`docs/OPEN_QUESTIONS.md`), alongside the grid_alignment mosaic/interim caches — no key design proposed here, per that OQ's resolution protocol. A change to `excluded_land_cover_tiles` does NOT create wrong results for tiles that get processed (it only changes which tiles are even in the list passed in; a tile's own cached result doesn't depend on which other tiles were excluded) — this is not a vulnerability of this cache, unlike the algorithm-version gap above.

- **D-F1b-009 — land_cover tile-cache key made content-stable, not content-and-mtime (task F1-3 item C, 2026-09-23).** `_land_cover_tile_cache_key()` (`raster_inspection.py`) previously concatenated `stat.st_mtime_ns`, `stat.st_size`, the tile's sha256 and the masking-polygon fingerprint into one string, compared whole (`_load_land_cover_tile_cache`, exact string equality) — so a re-fetch of byte-identical content (same URL, same bytes, new mtime) still missed the cache, because the *whole string* differed even though the embedded sha256 alone would have matched. This is the confirmed mechanism behind the "BRA F1b total runtime" entry below: F1-2's acquisition rerun rewrote all 111 BRA tiles (new mtimes), invalidating every cache entry regardless of whether that tile's bytes had actually changed. Fixed by dropping mtime/size from the key (`f"{sha256}:{geom_fingerprint}"` only) — correctness is unchanged (content that really changes still changes the sha256, still misses); only the false-invalidation-on-identical-content case is fixed. All three existing cache tests (`reuses_cached_tile_without_reopening_it`, `invalidates_cache_when_tile_changes`, `without_cache_dir_recomputes_every_time`) still pass unmodified. Tile-cache JSON files live under `outputs/<country>/data_quality_audit/land_cover_tile_cache/` — covered by the repo-wide `outputs/` entry in `.gitignore`, not a gap.
