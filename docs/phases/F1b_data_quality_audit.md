## Active implementation decisions

- **D-F1b-002 — M-F1b-01 expectations moved to config/audit.yaml, sourced from native file metadata.** `audit.py`'s five hardcoded literals (`_EXPECTED_RESOLUTIONS_DEG`, `_RESOLUTION_TOLERANCE`, `_SOLAR_PVOUT_SANITY_RANGE`) are gone; `run_audit_phase()` now takes an `AuditConfig` (loaded from `config/audit.yaml`) and `diagnose_consistency()` returns `(alerts, not_audited)`. Every configured value's `source` is either a primary reference or the layer is `null` with an OQ ID (OQ-027 to OQ-030) — resolved by reading GDAL metadata directly off the BRA/PRT files on disk (land_cover 0.0000833 deg, solar 0.0083333 deg, elevation 0.005 deg, wind-speed 0.0025 deg — all agreeing across both countries). PVOUT's unit was corrected to `kWh/kWp/day` (file's own XML metadata; matches M-F1-02 — the divergence was in the code, not METHODOLOGY). `slope` stays permanently null: it's a grid_alignment-derived product, never an F1b input (see OQ-030). Layers with no fetch path at all (3 GWA products, CMIP6, ERA5, GEM) are now reported `not_audited` unconditionally instead of omitted. `AuditResult` gained `not_audited: dict[str, str]`; `AuditSummary` gained `n_not_audited`.
- **D-F1b-001 — Vector inspection distinguishes read_error from processing_error; WDPA repair is no longer audit-specific.** `inspect_vector_layer()` used to swallow both a file-open/clip failure and a downstream statistics failure into one `error` field, labeled "found (unreadable)" — indistinguishable without reading logs. Two try/except stages now set `error_type` (`"read_error"` | `"processing_error"`), and `VectorLayerSummary.status` mirrors that split in the audit report footer. Separately, the `[ERROR] found (unreadable)` PRT/protected case (`TopologyException: side location conflict`, confirmed pre-existing against unmodified commit `e1a57ed`, see History) was resolved as a side effect of moving invalid-geometry repair into the shared `clip_vector_to_country()` — not touched here directly. Real PRT run 2026-09-21: 14/184 WDPA features repaired (`Too few points in geometry component` x7, `Self-intersection` x5, `Ring Self-intersection` x2), `protected` now reports `[OK] found`.

## Known issues

- `audit_report`'s artifact `schema_version` was bumped to `"2.1"` 2026-09-22 (main.py `_AUDIT_REPORT_SCHEMA_VERSION`) when `AuditResult` gained the required `not_audited` field (D-F1b-002) — a manifest entry recorded under `"2.0"` or earlier now correctly raises `StaleManifestEntryError` on resume instead of a raw Pydantic `ValidationError`.
- `population` has no configured `expected_resolution_deg` in `config/audit.yaml` and is not in the `not_audited` set either — it was never checked before D-F1b-002 (no literal existed for it in the old `_EXPECTED_RESOLUTIONS_DEG`) and F7-1/F7-2 did not extend scope to it. M-F1b-01 technically requires it; tracked here as a gap, not an OQ, since no research is needed — it just needs a metadata read like the other four.
- Land-cover inspection for BRA takes about 37-55 minutes. Per-tile caching implemented 2026-09-22 (`inspect_land_cover_tiles(..., cache_dir=...)`, `raster_inspection.py`): each processed tile's class-area contribution is persisted as its own JSON under `outputs/<country>/data_quality_audit/land_cover_tile_cache/`, keyed by the tile's mtime+size+the masking polygon's fingerprint. A run interrupted partway (real incident, 2026-09-22: a computer suspend killed a BRA run near tile 60/112) now resumes from the last cached tile instead of restarting from zero. Performance-only, no result change — see METHODOLOGY change protocol, no decision entry needed.
- `audit_report`'s artifact `schema_version` was bumped to `"2.0"` 2026-09-21 (main.py `_AUDIT_REPORT_SCHEMA_VERSION`) when `VectorLayerSummary.status`'s literal set changed — a manifest entry recorded under `"1.0"` now correctly raises `StaleManifestEntryError` on resume (METHODOLOGY A-02/A-09, docs/phases/core.md) instead of a raw Pydantic `ValidationError`. Any future breaking change to `AuditResult`'s shape needs the same bump.
- The 2026-09-22 FD4c `force_rerun` audited the corrected, geometry-filtered `land_cover` registry (BRA 112/155 tiles, PRT 11/26 tiles — see `docs/phases/F1_data_acquisition.md` Known issues) end to end; both audits completed and reported `success`. BRA's land-cover inspection took ~55 minutes this run (up from the ~37-minute figure above, consistent with more real per-tile geometry work now happening, not a regression).
