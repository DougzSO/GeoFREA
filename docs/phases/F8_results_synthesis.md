# F8 results_synthesis

Methodology items: M-F8-01, M-F8-02, Section 10

## Contract

Requires: persisted artifacts of F4 (`members`), F5 (`potential_aggregates_<tech>`), F6 (`supply_curve_<tech>`), F5 (`potential_<tech>__central`, `potential_density_<tech>`), F6 (`lcoe_nominal_<tech>`), F7 (`max_regret_<tech>__core` raster, `robustness_`, `hypothesis_`, `h1_summary_`, `h2_summary_`, `h3_summary_`, `h4_country_`, `h5_summary_`, `prim_box_`, `prim_bootstrap_`, `prim_boxes_`, `hazard_exposure_` and `potential_below_tau_<tech>__<window>`) and F7b (the four validation tables), all read through the manifest of the country (`inputs.py:ArtifactReader`), the `h4_verdict_<tech>__<window>` tables of the support phase `cross_country_h4` when its manifest exists (`outputs/cross_country/manifest.json`, read with the same reader and the same hash check), and the configuration files for T-M2 and T-M3. Produces, per country, under `outputs/thesis/` (`outputs/thesis__<scale id>/` at another scale): tables as `.csv` and `.tex`, figures as `.png` and `.pdf`, a `<stem>.provenance.json` beside each output, and `thesis_manifest.json` (what was built and what was not, per country). The phase registers `results_synthesis.json` (the summary).

## Active implementation decisions

Decisions D1 to D10 of `docs/_audit/2026-10_F8_design.md` that the first nine scripts use were accepted on 2026-10-13 as the report recommends.

- **D-F8-001 — Reader (report section 2, item 2).** `ArtifactReader` finds an artifact by its manifest key, checks the file against the SHA-256 registered with it, refuses a Parquet table whose schema version is not the one named, and records what it read so that each output cites it. A path is never built by hand. F8 imports no kernel, evaluator, eligibility engine or pipeline; a test scans the imports against an allow-list and a second test checks in a fresh process that loading the runner loads none of those modules.
- **D-F8-002 — D1(a): style (recommended, accepted 2026-10-13).** `style.py` extends `overview/style.py` (the map style) with fonts, sizes, one colour per SSP, one for the reference member, one per technology by its position in the run's list, and a deterministic save (no creation date or software tag).
- **D-F8-003 — D4(a): `figures` (recommended, accepted 2026-10-13).** Thesis outputs do not follow `settings.yaml` `figures`; a thesis build always writes everything. Names are `T-<id>_<what>_<ISO3>_<tech>.<ext>` (`names.py`).
- **D-F8-004 — D5(a): weighting (recommended, accepted 2026-10-13).** One weighting across the thesis: capacity. The nine outputs show F7's statistics as F7 wrote them (H2 and H3 are already capacity-weighted); F8 weights nothing itself.
- **D-F8-005 — D7(a): missing inputs (recommended, accepted 2026-10-13).** A script builds what exists and records what it did not build, with the reason, in `thesis_manifest.json` and in the phase summary; a table that a producer wrote empty (null `tau`, no hazard threshold, no published estimate) is written empty with the reason in its caption, never as zero. The run fails only when an Essential T-ID has no output at all for the country (`ThesisBuildError`).
- **D-F8-006 — D8(a): what is built before real data (recommended, accepted 2026-10-13).** Everything of section 4 of the report on the synthetic country; the real build waits for the real F7 and F7b. The first group of nine outputs is built now: T-M2, T-M3, T-R2, T-R6, T-R9, T-R10, T-R12, T-O2, T-O3. None of them depends on D2 or D6.
- **D-F8-007 — D9(a): test values (recommended, accepted 2026-10-13).** A thesis build refuses a parameter that is a proxy or a test value, and an uncertain parameter without a value or a range (`ThesisValueError`). A country whose every value is a test value (the synthetic fixture) is built as a test build, which stamps "TEST VALUES" on every caption and in every provenance file.
- **D-F8-008 — D10(a): formats (recommended, accepted 2026-10-13).** Tables as CSV and LaTeX (booktabs; the unit table of T-R9 as CSV only), figures as PNG and PDF, a provenance JSON per output (artifact keys and hashes, configuration hashes, METHODOLOGY version, scale, caption) and `thesis_manifest.json` per thesis directory.
- **D-F8-009 — Scales (V-07, T-R6).** The run at the default scale writes `outputs/thesis`; a run at another scale writes `outputs/thesis__<scale id>` so it never overwrites the thesis outputs. T-R6 reads the manifests of both scales and shows the rows of the 2071-2100 window and of the other scale beside the core ones.
- **D-F8-010 — Outputs not built here and the decision that blocks each.** Every T-ID of Section 10 now has a script. T-R3 waited for D2 and T-R8 for D6; both were built when the decision was closed (D-F8-018, D-F8-014). What no script can give before the real runs is listed in Known issues.
- **D-F8-011 — T-R6 reads H1, H2 and H3 (2026-10-13).** T-R6 per technology writes `hypothesis_statistics` (the H1, H2 and H3 rows of the F7 hypothesis table, core window, 2071-2100 window and other scale), `hypothesis_verdicts` (one row per hypothesis, window and scale: the primary statistic, its reference value, the pre-registered threshold, the verdict and the rule as F7 applies it; H1 has two primary statistics, H1a in `statistic` and H1b in the columns ending in 2) and the summaries `h1_summary`, `h2_summary` and `h3_summary` with their sensitivities. The verdict row is the primary row of the F7 summary, so F8 recomputes nothing; a summary written empty (null rule or null `top_k_percent`) gives no row and the reason is recorded as a skip.
- **D-F8-012 — T-R7 and the H4 row of T-R6 read the support phase (2026-10-13).** H4 compares countries, so its verdict is written by `cross_country_h4` (D-F7-049) under `outputs/cross_country`, and F8 reads that manifest through the same `ArtifactReader` (`BuildContext.cross_country`, one reader per scale that has a manifest; the provenance lists what was read under `artifacts_read_cross_country`). T-R6 `hypothesis_verdicts` gains one H4 row per technology, window and scale (`h4_strict_pair_count`: the pairs of a Climate-Dominated and a Techno-Economic-Dominated country, threshold 1; `countries_with_profile`, at least 2), and the tables `h4_country` (this country) and `h4_verdict` (all the countries, no ISO3 in the name). T-R7 per technology writes `T-R7_axis_displacement_<tech>` as table and figure, with no ISO3 in the name because it is about the countries together: left, `D_clim` and `D_tec` by country; right, `rho` with the boundaries of `hypothesis_rules.H4` and the profile bands; an unavailable country is shown as such and a country with no displacement has no point. Until `cross_country_h4` has run, T-R7 shows the country alone from its own `h4_country` table and its caption says so, and T-R6 records a skip for the H4 row. `main.py` runs the support phase after the country runs and then builds the thesis outputs of the countries again, so the real build has both. A null `hypothesis_rules.H4` builds no T-R7 (reported, D7).
- **D-F8-013 — T-R6 gains the H5 row; T-R10 and T-R12 are coherent with it (2026-10-14).** T-R6 per technology now reads the `h5_summary` table too: `hypothesis_statistics` has the H5 rows of the F7 hypothesis table, `hypothesis_verdicts` one H5 row per window and scale with two statistics as H1 (`h5a_resource_loss_ratio` in `statistic`, `h5b_exposure_ratio` in the columns ending in 2, both against `lambda`) and the table `h5_summary` shows the target, the slack and the sensitivities. The verdict column holds the verdict of the primary row, or, when there is none, why: `not_testable` (no target), `target_not_met_at_reference` or `exposure_not_available` (no hazard member or a null threshold; the 2071-2100 window). A summary written empty (null rule or null `tau`) gives no row and the reason is recorded as a skip. T-R10 and T-R12 are the tables F7 builds with the calculations of H5 (D-F7-052), and a ZZZ test checks that the totals agree: the largest `any_channel` exposed energy over `economic_domain` equals the exposed energy of H5b, the `fixed_domain` series of the reference member equals `E_0`, and the largest reduction over the core members equals `Delta E`.
- **D-F8-014 — T-R8: no aggregate verdict (D6 closed, 2026-10-14).** The decision D6 of `docs/_audit/2026-10_F8_design.md` (how the verdicts of H1 to H5 combine across countries) is closed by METHODOLOGY 13.0.0, M-F8-03, and OQ-050 is removed: the synthesis reports what was observed and combines nothing into one verdict or score. `synthesis.py:t_r8` writes, per country, `T-R8_hypothesis_profiles_<ISO3>.json` (the structured profiles), `T-R8_country_summary_<ISO3>.md` and `.tex` (the readable summary), and, about the countries together (no ISO3 in the name), the tables `T-R8_country_profiles` and `T-R8_hypothesis_summary` (CSV and LaTeX) built from the profile files of every country in the thesis directory. The directory is shared by the countries, so a build run after every country has been built (as `main.py` does after `cross_country_h4`) shows all of them; a build before that shows the countries built so far.
- **D-F8-015 — Profiles: content, ranges and classes.** A record per country and technology holds the window, the size of the candidate set and of the F7 set, `k` and, for each hypothesis, the class (the verdict, or why there is none), the primary statistics with their reference and threshold, and the range of each over the rows of its F7 summary: the sensitivity variants of the core window, the primary row of the 2071-2100 window (`window_2071-2100`) and the primary row of the other cell scale (`scale_<id>`) when they exist. `n_variants_changing_verdict` counts the variants whose class is a verdict that differs from the primary one (a variant with no verdict never counts). H1 splits its partial class by the sub-hypothesis that holds (`partially_supported_core_stable`: only H1a; `partially_supported_vulnerable`: only H1b), H5 has its two partial classes from F7, and both are listed in `synthesis.partial_classes_separate`. H4 holds the country profile with its variants and, from the support phase, the verdict of the technology and the profile of every country. A hypothesis whose F7 table is empty is `unavailable`, with the reason.
- **D-F8-016 — The summary and the labels.** `synthesis` in `experiments.yaml` (`SynthesisConfig`, "OQ-050 (T-R8), pre-registered 2026-10-14") holds the three labels, the minimum of two testable cases and the rule `all_testable_same_verdict`. A case is testable when its class is a verdict (supported, a partial class, not supported); `not_testable`, `target_not_met_at_reference`, `exposure_not_available` and `unavailable` are counted by class and never make a pattern context-dependent. H4 has no label: the row shows the verdict of the technology and the count of countries by profile.
- **D-F8-017 — T-O1.** One table and one figure per technology from `prim_box`, `prim_bootstrap` and the trajectory `prim_boxes`: the box chosen is drawn on the position of its limits within the range of each restricted descriptor (the range is the box with every future), with a line for the 5th to 95th percentile of the bound over the replicates, the share of replicates that restrict each descriptor beside its name, and the density and coverage with their percentiles in the title; a categorical descriptor shows the categories kept. A primary search that ended as `no_cases`, `all_cases` or `no_eligible_box` draws nothing and records the status as the reason. In the ZZZ run the real outcome is zero everywhere (the synthetic world keeps the order of its cells), so the test replaces it by a rule on the GCM.

- **D-F8-018 — T-R3: the GCM-agreement convention (D2 closed, 2026-10-14).** A cell is marked when at least two thirds of the GCMs of an SSP agree on the sign of the change of the capacity factor, the convention of the IPCC AR6 WGI Atlas (reference in METHODOLOGY Section 13, verify; the share is Tier 3 and lives in `thesis_figures.gcm_agreement.min_share`, `"2/3"` as a fraction so that two of three members pass). The change of a member is `CF` of the member minus `CF` of `m0` from `potential_<tech>__central`; the map shows the median over the members of the SSP in the core window (one member per GCM). A member without a value in the cell (M-F4-07) and a change of exactly zero agree with no sign, so they count against the agreement: the marking is conservative. The marking is a presentational reduction of persisted values (G3), computed in F8 with `agreement_mask`; the table `T-R3_cf_agreement` gives the share of cells in agreement per SSP.
- **D-F8-019 — T-M1: the graph is the orchestrator's.** `orchestrator.py:phase_graph` returns, after the validation of a run, the phases and the phases each depends on; `main.py` gives it to `build_thesis(phase_graph=...)` and `dag.py` lays it out by layers (the longest chain of dependencies) and draws it; the edges are in the provenance. `thesis_figures.dag_axes` lists the phases on the member axis and on the sample axis; a name that is not a phase is an error. A build that is not started by `main.py` gives no graph and T-M1 is not built, with the reason (T-M1 is Essential).
- **D-F8-020 — T-R1 and T-R11 read the diagnostic COGs.** The maps of F5 and F6 are registered artifacts (`potential_density_<tech>`, `lcoe_nominal_<tech>`); F8 reads them through the manifest (hash checked) and draws them with `style.thesis_style`, not the diagnostic PNGs. A raster with no value is not drawn and the reason is listed.
- **D-F8-021 — T-R4 and T-R5.** T-R4 reads the raster `max_regret_<tech>__core`, the cells of `robustness_<tech>__core` (`mr`, `admin1_id`, `p_mw`) and the statistic `h2_mr_capacity_weighted_national`; the box plot of the cells within each region shows the 20 regions with the most capacity. T-R5 reads `nominal_rank`, `robust_rank` and the top-k flags, the stored `h1_ssp_jaccard__<pair>` rows and `c_k` of `h1_summary`; no ranking is recomputed (D3 resolved by the H1 pre-registration).

## Known issues

- The LaTeX tables and the PDF figures have not been compiled in an environment with a TeX engine.
- Needs real values (the scripts run on ZZZ): T-R1, T-R3, T-R4, T-R5 and T-R11 and every table need the F5 to F7 runs of BRA, PRT and IND (OQ-004, OQ-005, OQ-023; OQ-001, OQ-016 to OQ-019, OQ-022; OQ-008, OQ-021); T-R6 and T-R8 for H5 need the targets (OQ-010) and the thresholds (OQ-051); T-R9 shows the published comparison empty until OQ-057; T-R7 and the H4 row of T-R8 need the three countries; the legibility of T-R4 with 180,000 cells (BRA) cannot be judged before the real run.
- The real thesis build needs the real F5 to F7b runs, the national targets of OQ-010 and the hazard thresholds of OQ-051 for H5 (without them H5 is not testable or has no exposure), and the sourced parameter values (D9 refuses test and proxy values).
