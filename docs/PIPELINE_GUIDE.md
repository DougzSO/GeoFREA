# GeoFREA pipeline guide

Scope: what the pipeline of v2 does, when a phase runs again, what the phases of the kept chain cost, and how to run it. Authority: `docs/METHODOLOGY.md` (method) and `docs/phases/<phase>.md` (contract and decisions); where this guide disagrees with either, the other one wins and this guide is the defect. The code still holds the phases F4, F7 and F8 of v1 until they are rebuilt; this guide describes the chain that v2 keeps.

## 1. The graph

The orchestrator (`core/orchestrator.py`) builds the order from the `requires` and `produces` of the `PhaseSpec`s registered in `main.py`; nothing else fixes the order. The phases of `run.target_phases` (`config/settings.yaml`) are the default round; later phases are named with `--phases`. The v2 DAG is in `docs/METHODOLOGY.md`, Section 4.1.

## 2. How a phase decides to run, resume or skip (all phases)

One rule, in `core/orchestrator.py`, applies to every phase:

1. **Resume** (log: `Phase '<name>' [ISO]: resuming — manifest status 'success' ... Skipping re-execution`) when the manifest entry is `success`, its `code_fingerprint` equals the current one (normalised AST of the modules the phase imports, `core/code_fingerprint.py`; a comment or a docstring does not change it),
   its `config_fingerprint` equals the current one (`core/config_fingerprint.py`: only the parameters the phase reads), the artifacts recorded for the phase are exactly the ones the phase produces (`StaleManifestEntryError` otherwise), and every artifact is on disk with its recorded sha256.
2. **A missing or altered artifact stops the run; it does not trigger a recompute.** `ArtifactIntegrityError: ... no longer matches its recorded sha256 ... Not recomputing`. The remedy is to name the phase: `--rerun <phase>`.
3. **Execute** otherwise, with the reason in the log: `named in rerun_phases (forced)`; `the configuration it reads changed since it ran`; `the code it runs changed since it ran`; `manifest status 'stale_upstream' (or 'failed'), does not resume`; `no manifest entry yet`.
   When a phase executes, its dependents are marked `stale_upstream` and are recomputed the next time a run needs them, without being named.
4. **Revalidate** (`--revalidate p1,p2`): a `stale_upstream` entry whose inputs are unchanged is declared valid again, after the orchestrator checks that its required artifacts exist; used once after a contract change.
5. `--rerun p1,p2` (or `run.rerun_phases`) forces exactly those phases and never their dependents.
6. The manifest is written to a temporary file and moved into place, so a killed process leaves the previous manifest, not a half file. **A killed run can still leave a half-written artifact**: the byte hash then differs and the next run stops as in item 2.

Inside a phase the **internal caches** decide what is reused when the phase does execute (section 3 gives the key of each). Every cache key contains the content of its inputs and `cache_code(name)` (the fingerprint of the code that computes the cached result, `core/cache_code.py`), so a change of the computing code is a cache miss, never a stale hit.
A change that must not change a result is proved by the canonical content hash before it is accepted (CONVENTIONS, "Changes that must not change a result"); the aligned layers of an older code are adopted only with a proof (`scripts/adopt_aligned_cache_keys.py`, D-core-044).

Robustness common to all phases: pydantic schemas on every phase output (`output_model`) and on every table (`table_schemas.py`, `schema_version` in each Parquet); fail-loud on a missing required parameter (`MissingParameterError`) and, with `--production`, on a proxy or an uncertain parameter without a range;
sanity ranges from `config/audit.yaml` (F1b) and invariants V-03 (eligible area <= cell area, cell total = pixel total) raise rather than warn; a memory guard refuses a cold audit or F2a with less than 2 GB available (exit code 75, before any phase of any country);
`keep_awake` asks Windows not to sleep during a run.

## 5. How to run

Always from the repository root with the project's interpreter; `GEOFREA_DATA_DIR` and the other directories come from `.env` (never commit it; it holds API credentials).

```
python main.py PRT                                  # default round (10 target phases) for one country
python main.py PRT IND BRA                          # several countries, one after the other
python main.py PRT --phases technical_potential,potential_maps   # F5 and the maps; upstream phases run if needed
python main.py PRT --phases overview --rerun overview            # rerun exactly one phase (never its dependents)
python main.py PRT --revalidate land_eligibility                 # a stale_upstream entry is still valid
python main.py PRT --production                                  # refuse proxies and uncertain parameters without a range
python main.py PRT --scale 0p1deg                                # the V-07 scale check (files under <phase>__0p1deg)
python main.py PRT --phases lcoe_modeling --real-run             # F6 onwards on a real country needs --real-run (else refused, nothing runs)
python main.py PRT --phases lcoe_modeling --plan                 # what the invocation would execute, resume or find stale; runs nothing, writes no manifest
```

* **F6 onwards and `--real-run`.** The phases `lcoe_modeling`, `sample_size_convergence`, `robustness_analysis`, `cross_country_h4`, `external_validation`, `lcoe_maps`, `robustness_maps` and `results_synthesis` run on a real country only when the invocation carries `--real-run` (a refusal lists the phases and starts nothing; `scripts/run_unattended.ps1` passes the option when its `-Phases` names one of them). A synthetic country does not need it. The check of the pre-registration (the tag `prereg-v1`, L-244) is separate and still applies with the option.
* **`--plan`.** Per country, the phases the invocation would execute, resume or find stale, with the reason, from the manifest and the fingerprints (`Orchestrator.plan`); it executes nothing, writes no manifest and does not open the log of the run. It does not hash the recorded artifacts, which a run verifies before it resumes a phase.
* **Figures.** `figures: all | summary | none` in `config/settings.yaml` (there is no flag). `summary` is the development setting; `all` only for the thesis build. Changing it reruns the figure phases and no other.
* **Autonomous round** (several countries, nothing else open; it needs about 4 GB free for IND and BRA):
  `powershell -ExecutionPolicy Bypass -File scripts\run_unattended.ps1 [-Countries IND,BRA] [-DryRun]`. It adopts the aligned layers, runs every phase with `--rerun`, compares every artifact with the saved manifest and writes `outputs/<ISO>/unattended_check.json` and `logs/unattended_rounds/unattended_round_<stamp>.json`. Exit code 0 only when every country is IDENTICO.
* **Adopt the aligned layers made by an earlier code** (once per country after a change of the code of the aligned layers; it stops unless the proof says "equal"):
  `python scripts/adopt_aligned_cache_keys.py <ISO> --revision adopt-base-75 --proof docs/evidence/infrastructure/proofs_75_77/cumulative_equivalence_77_PRT.json` (`--check` resolves the revision and the proof without adopting). Without it F2a is rebuilt (6,878 s awake in IND, 18,707 s in BRA).
* **Is the data still what the manifest says?** `python scripts/check_manifests.py [PRT IND BRA]` (about 10 minutes for the three; `--bytes` also compares byte hashes).
* **Substations.** The substation layer is not a registered layer of `data_acquisition`: it is the file written by `python scripts/fetch_osm_substations.py PRT IND BRA` (Overpass, network needed), read by F2a (M-F2a-09).
  **Cold round, order and exact commands.** F2a, F2b and F3 of one country per call, in this order: PRT, then IND, then BRA, from a PowerShell window with Claude Code, VS Code and the browser closed, each call after the previous one printed `ROUND FINISHED`:
     `powershell -ExecutionPolicy Bypass -File scripts\run_unattended.ps1 -Countries PRT -Phases grid_alignment,siting_layers,land_eligibility -SkipAdopt -Worktree <this tree>`
     `powershell -ExecutionPolicy Bypass -File scripts\run_unattended.ps1 -Countries IND -Phases grid_alignment,siting_layers,land_eligibility -SkipAdopt -Worktree <this tree>`
     `powershell -ExecutionPolicy Bypass -File scripts\run_unattended.ps1 -Countries BRA -Phases grid_alignment,siting_layers,land_eligibility -SkipAdopt -Worktree <this tree>`
     The check at the end lists `aligned/population` (exact area-weighted sum, D-F2a-026) among the differences by design, with `roads`, `poi` and the F3 tables; read each one. Measured peaks per layer: `config/memory_budget.json` (cap 1,536 MB per process; `docs/evidence/infrastructure/memory_budget_88.md`).
  **Paging file (Windows).** Set the paging file of the system drive to 16 to 24 GB (System, Advanced, Performance, Virtual memory: custom size, initial = maximum, then restart) before the round of IND or BRA. The machine has 5.9 GB; the layers of F2a peak at 0.4 to 1.5 GB each but F3 of BRA peaks at 3.4 GB, and what the guard reads is the commit charge (physical memory plus the paging file), not the free physical memory.
  **Behaviour of the guard.** Before each layer of F2a and F2b the child process waits until the free physical memory covers the measured peak of its kind plus a margin (`memory_guard.wait_for_memory`); every wait is logged with its reason and the time waited, in the ledger of the layer. Nothing is stopped for low free physical memory, which is normal on a machine that pages. The process tree of the country is stopped only when the commit charge of the system passes 95 % of its limit (`-MaxCommitPercent 95`): the country is then marked `ABORTADO` and the round goes on to the next; the manifest keeps the phases that finished.
  **Reference store.** `GeoFREA_data/references/` keeps the outputs of the rounds the pipeline accepted: `objects/` (each file once, named by its SHA-256), `<run_id>/<ISO>/index.json`, `<run_id>/<ISO>/manifest.json`, `<run_id>/<ISO>/files/` (hard links) and `latest.json` (the `run_id` is the one of the code of the run, shared by the countries of a round, so a round is the pair run_id and country). A round is accepted when it executed a phase, every phase ended `success` and the deferred check has no phase DIFERENTE; the pipeline then keeps the JSON summaries and the aligned and F2b rasters of the country (what is kept: `reference_store` in `config/deferred_checks.yaml`), with nothing to run by hand. A resumed round, a failed one or one the check stopped is not kept (the log says why). PRT, IND and BRA compare with `latest` (`baseline: latest` and `reference_run: latest`): the hashes with the manifest of the last accepted round, a raster whose hash differs with its file by tolerance. The first round is the state of 2026-11-04, kept by hand with `python scripts/publish_reference.py PRT IND BRA --note "..."` (it runs the check on every listed phase and refuses a country with a phase DIFERENTE; the phases that are `stale_upstream` are left out until they are rerun). The rounds imported from `backup_before_89` with `scripts/seed_references.py` (`seed_20261102_<ISO>`) are `historical`: kept, not deleted; pin one with `reference_run: seed_20261102_BRA` to compare with it. The store takes disk (BRA aligned layers about 1.4 GB, once; a later round adds only the files that changed): `objects/` can be pruned of the files no `index.json` lists.
  3. **Estimated awake time**, cold F2a, from the profiles above: PRT about 3 minutes (F2a 139 s, F3 17 s); IND about 2 hours (F2a 6,878 s, F2b 27 s, F3 470 s); BRA about 5.5 hours (F2a 18,707 s, F2b 58 s, F3 1,117 s). The `poi` step adds the voltage inference for 8,662 to 17,056 substations to each country (minutes, not measured). F4 is unchanged and F5 recomputes from the new F3 tables with the same numbers. F6, F7 and F8 are not part of this round: F6 refuses to run until OQ-001 (unit costs) and OQ-066 (ACER price year) are closed.
* **Tests.** `python scripts/affected_tests.py` selects the tests of the changed files; the full suite (`python -m pytest`) is the gate of a merge and runs with nothing else open.
* **The memory rule.** A cold `data_quality_audit` or `grid_alignment` does not start with less than 2 GB available (exit code 75, before any phase of any country; `core/memory_guard.py`). The machine has 5.9 GB: close the browser and the editors before a cold IND or BRA, never run two countries at once, and expect peaks of 2.3 GB (IND F3), 3.4 GB (BRA F3) and 2.7 GB (BRA hazard_context). The cold IND round died twice, silently, near 1 GB available (`profile_76.md` D).
* **Sleep.** `keep_awake: true` asks Windows not to suspend during a run; the sleep of a long run is subtracted from times with `scripts/profiling/export_power_events.ps1` and `parse_logs.py`.
* **After a killed run**: if the next run stops with `ArtifactIntegrityError`, name the phase (`--rerun <phase>`); do not delete manifest entries by hand.
* **After an interruption.** A power loss, a killed process, the memory guard or Ctrl+C loses at most the unit of work that was running; the run continues from there with a result equal by content hash to the continuous one.
  1. `python scripts/verify_cache_integrity.py [IND PRT BRA]` reads every cached file to the end, compares the manifest's size and hashes, and removes the cache key (never the file) of what is cut or changed; the report is `<data>/logs/integrity/integrity_<stamp>.md`. `--dry-run` only reports, `--include-raw` also reads `raw/` (about 60 GB).
  2. `powershell -ExecutionPolicy Bypass -File scripts\run_unattended.ps1` with no flags continues the unfinished round (`scripts/unattended_resume.py`): the same stamp, countries and phases, the manifest saved before the round kept, the finished countries skipped (`outputs/<ISO>/unattended/<stamp>/done.json`), the adoption not repeated (`adopted.ok`). `-NewRound` starts another one.
  3. The units that survive are in `interim/<ISO>/<phase>/<item>_ckpt/` (`core/checkpoint.py`, valid only for the same code, inputs, grid and parameters, else dropped with a warning; removed when the work is recorded; bounded by `checkpoint_max_gb`): F2a elevation, slope and bins by 32 rows of the grid, land-cover counts and mosaic by tile; F3 shares by strip; F6 by member; F7 by member (evaluation), by batch of draws and by batch of bootstrap replicates (with the state of the generator). Downloads of DEM and WorldCover tiles continue their `.part` with a `Range` request.
  4. Not protected inside the unit (see `docs/LIMITATIONS.md` L-063 and `docs/evidence/infrastructure/checkpoint_98.md` section 8): the first vector clip of a large layer in F1b, the GWA, ERA5 and CMIP6 downloads (their own atomic `.part` files, no flush; GADM zip written in place), the WDPA page crawl, and the small JSON side files.
  5. To continue a round by itself when the user logs on (documented, not enabled): `schtasks /Create /TN "GeoFREA resume" /SC ONLOGON /TR "powershell -ExecutionPolicy Bypass -File D:\Douglas\DOUTORADO\GeoFREA\scripts\run_unattended.ps1"`; remove it with `schtasks /Delete /TN "GeoFREA resume" /F`. The script refuses to start when another GeoFREA process runs or less than 1,800 MB is free, so a task that fires at a bad moment only logs and stops.
