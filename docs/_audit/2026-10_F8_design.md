### 1.3 Facts that bind the design

1. **Windows and scales.** F7 writes both windows in one run, by role (`core` 2041-2070, `sensitivity` 2071-2100) under the active scale; the 0.1 degree check writes under `<phase>__0p1deg`. T-R6 needs rows for 2071-2100 and 0.1 degree, so F8 reads two directories.
2. **Technology-neutral code.** F8 is an F5-F8 phase: no ISO3 literal and no technology name in the source; the technologies come from `run.technologies` and the countries from `settings.yaml` (A-04).
3. **Null decision parameters.** With null `tau`, `CF_min`, `p_k`, a hazard threshold or a hypothesis rule, F7 writes empty flagged tables or `verdict = null`. F8 must therefore treat a skipped table as "not available", never as zero, and print the flag in the caption.
4. **Essential and optional.** Section 10 marks T-O1 and T-O2 Optional; the other sixteen are Essential.
5. **Figures setting.** `settings.yaml` `figures` (`all`, `summary`, `none`) governs diagnostics. Thesis outputs are produced "only by F8" (CONVENTIONS) and are not diagnostics, so D4 asks whether they follow `figures`.
6. **Where F8 sits in the DAG.** F8 requires artifacts of F5, F6, F7 and F7b. A thesis build for a country with F7b skipped (no inventory) cannot produce T-R9; the phase must say which T-IDs it did not build and why (D7).

## 2. Form of the phase

1. **One module per T-ID, one runner.** `src/geofrea/results_synthesis/` with `t_r4.py`, `t_r5.py`, and so on, each exposing `build(inputs, out_dir)`, plus `style.py` (extends `overview/style.py`) and `names.py` (the file-name rule). A script per output is M-F8-02; a module is the testable unit, and `python -m geofrea.results_synthesis.t_r4 ...` or `main.py --phases results_synthesis --thesis T-R4` runs one.
2. **Inputs are artifacts, found through the manifest.** A reader module `inputs.py` opens only the files that the manifest of each country registers (hashes checked), never a path built by hand, and refuses an artifact whose `schema_version` it does not know. This is M-F8-01 enforced: F8 imports no kernel, no evaluator and no eligibility code; a test (like the V-06 module allow-list of F7b) scans the imports.
3. **Naming.** `T-<id>_<what>_<ISO3>_<tech>.<ext>`, for example `T-R4_max_regret_BRA_solar.png`, `T-R2_potential_range_BRA_solar.csv`; a cross-country output drops the ISO3 (`T-R8_synthesis.csv`). Tables are written as CSV and LaTeX (D10), figures as PNG and PDF.
4. **Provenance.** Each output gets a sidecar `<name>.provenance.json` with the artifact keys and SHA-256 it read, the METHODOLOGY version, the scale and the window. A thesis figure can then be traced to the run that made it, and a stale one (an input hash that changed) is detected.
5. **Style.** One style: font family and sizes, panel sizes for a page width, a colorblind-safe palette, the map style of `overview/style.py` (hillshade, outline, scale bar) for map figures, and a fixed colour for each SSP and each technology across all figures. No figure sets its own look.

## 3. T-R8 and the verdicts on H1 to H5

1. **What exists.** F7 evaluates each pre-registered rule of `hypothesis_rules` per country and technology and writes `rule`, `verdict` and `verdict_reason` on the rows of the statistic it names. A hypothesis can have several rules (a list). A null list gives no verdict and a warning (D-F7-023).
2. **What is open.** The statistic, comparison and threshold of every rule are OQ-050, the author's; they are fixed before the results are read. How the per-country, per-technology verdicts become one verdict on a hypothesis for the thesis is not written anywhere.
3. **The question T-R8 answers is RQ5**: does the framework generalize across the three countries or give context-specific results? H1, H2, H3 and H5 are stated as properties of each country; H4 states that there is no country-independent ordering. So the combination differs by hypothesis:
   - H1, H2, H3, H5: the statement is "holds in each country" or "holds in k of 3".
   - H4: the statement is about the ordering between countries, so it is read from the country ordering of the climate-only versus techno-only Jaccard difference (M-F7-07), not from a per-country verdict.
4. **The rule must not be invented by F8.** D6 offers the options. Whatever is chosen is written in the F8 record and in `experiments.yaml` before any real F7 result is read, as OQ-050 is.
5. **What T-R8 shows.** One row per hypothesis and technology; one column per country with the per-country verdict and the statistic's value (P10 to P90 over draws where F7 gives it); a last column with the combined verdict by the D6 rule; a `reason` column. A cell with no verdict is shown as "not evaluated: rule null" and never as "not supported".

## 6. Decisions for the author's verdict

Each has options; the recommendation is marked.

**D1. The style module.**
(a) Extend `overview/style.py` with a thesis figure style (recommended): one place, the maps already look the same, and a diagnostic can graduate to a thesis figure by changing the layer only.
(b) A separate `results_synthesis/style.py` with no link to the overview: independence, at the cost of two looks.
(c) No module; each script sets its own look: refused by M-F8-02 ("fixed style").

**D2. The GCM-agreement marking of T-R3 (G3).**
(a) F8 computes it from `forcing.parquet`: sign of the change of each member in the SSP and window, marked where at least a stated share of the GCMs agree (recommended: the IPCC AR6 convention of two thirds agreeing on the sign, stated in the caption).
(b) F4 persists a per-cell agreement raster, F8 reads it: keeps "F8 only reads" literal, adds an F4 output.
(c) Draw the median change and omit the marking, with a note: removes a deliverable of T-R3.
The threshold is a choice and a Tier 3 value if (a) is chosen; it goes in configuration, not in the script.

**D3. T-R5 and "top-k stability across SSPs" (G1).**
(a) The median over GCMs, by SSP, of the per-future Jaccard of the top-k with the nominal top-k and of the share of nominal top-k cells that leave (recommended; both exist in `futures_<tech>`; no change to F7).
(b) F7 also persists the top-k set per SSP so that a SSP-to-SSP Jaccard can be drawn: closer to the wording of H1 ("stable across the three SSPs"), at the cost of storage and an F7 change.
(c) Only the rank scatter: leaves "across SSPs" undrawn.
Option (b) is the better match to H1's wording; option (a) answers it indirectly through the nominal set. This is the one decision that may require an F7 change.

Resolved 2026-10-13 by the H1 pre-registration: F7 persists the top-k set per SSP in `ssp_scores_<tech>__<window>` (D-F7-035), which is option (b). T-R5 draws the SSP-to-SSP Jaccard from `ssp_scores` and `h1_summary`; the per-future Jaccard of option (a) stays available.

**D4. Do thesis outputs follow `settings.yaml` `figures`?**
(a) No: `figures` governs diagnostics; a thesis build is explicit (`--phases results_synthesis`) and always writes everything (recommended).
(b) Yes: `none` writes tables only.

**D5. Country aggregation of cell quantities in T-R7 (and any country mean in T-R4, T-R6).**
(a) Capacity-weighted, as H2 and H3 already are (recommended: one weighting across the thesis).
(b) Area-weighted.
(c) Unweighted over cells.

**D6. The combination rule of T-R8 across countries and technologies (the author's, pre-registered with OQ-050).**
(a) Per hypothesis, "supported" when every evaluated country-technology verdict is "supported", "not supported" when none is, "mixed" otherwise, and the count shown (recommended: the most transparent; it never hides a disagreement; it answers RQ5 as "context-specific" when "mixed").
(b) Majority of the six country-technology verdicts.
(c) Country-level verdicts only (technology pooled by the author's rule), then (a) over the three.
H4 is read from the country ordering whichever option is chosen (section 3). The rule goes in `experiments.yaml` (`synthesis_rules`) before the first real result is read.

**D7. A country or technology with no verdict or with a skipped table.**
(a) Build what exists; list in `thesis_manifest.json` each T-ID not built and why (null rule, empty flagged table, F7b skipped); exit non-zero only if an Essential output has no input at all for every country (recommended).
(b) Refuse to start while any rule is null: strict, and forces the order of work, but blocks the figures that do not need the rules.
(c) Build nothing without all three countries.

**D8. What is built before real data.**
(a) Everything in section 4 on ZZZ, T-R8 as mechanics only; the real build waits for the real F7 (recommended).
(b) Only the config tables and the F5 and F6 reads now; F7 reads after F7 runs on a real country.

**D9. Test values in thesis tables.**
(a) The thesis build refuses to read a proxy value or a missing range, as `--production` does for F5 to F7 (recommended); ZZZ is built with a `--synthetic` flag that stamps the output "TEST VALUES".
(b) Allow it with a visible mark.

**D10. Table formats and the provenance file.**
(a) CSV and LaTeX tables, PNG and PDF figures, a sidecar provenance JSON per output and one `thesis_manifest.json` per build (recommended).
(b) CSV and PNG only.
(c) Add a Word-compatible table (xlsx).
